obsidian+remnote 应用渐进阅读的一种新尝试（开箱即用）

  • obsidian+remnote 应用渐进阅读的一种新尝试（开箱即用）
    • 渐进阅读进阶开发的核心难点是没有好的算法，原因有两个。
      • 可借鉴的原始版本几乎为零。
        • 市面上只有针对知识复习的间隔重复算法。
        • 渐进阅读需要以保留度、可提取度作为指标进行分析。
        • 把现有间隔重复算法直接应用到渐进阅读上，属于错误的挪用。
          • 类似手上有锤子，就看什么都像钉子。
          • 渐进阅读必然需要全新的算法。
        • 该文章也提到了这一点，这篇文章的作者应该是国内社区最早提出该观点的

          • https://zhuanlan.zhihu.com/p/1977318534276194737

      • 渐进阅读中的很多参量难以量化。
        • 知识复习、提取练习相对可量化。
        • 重要性、紧急度、难度、兴趣等维度难以量化。
    • 渐进阅读至今没有非常完善的工作流。
      • 尤其是能把优先级和算法结合起来的工作流。
      • 这是目前还没有一个完善且能服众的方案的重要原因。
    • 这篇文章的核心
      • 概括并表达我对渐进阅读的想法、观点和理解
      • 顺便分享这一套工作流
      • 开发这件事情本身并不重要
        • 几乎100% vibe coding
    • 分模块、分应用场景介绍工具与相应工作流
      • 这个工具分为三个模块
        • 输入采集
          • 即解决稍后阅读的问题
          • 如果渐进阅读只能处理本地文件，甚至只能处理某一种特殊格式的文件，如 Markdown/Epub，那么距离渐进阅读的真正使用就永远存在最后一公里
          • 支持把网页、PDF、EPUB 清洗为并分节为标准的 MD 格式
            • 对latex，代码块等做了特化处理，支持数理lecture
          • 支持PC全界面选中文字/截图 后剪藏
          • 开放接口，用于更高级的批量/个性化操作
            • 批量导入自己的知乎收藏、知乎点赞
        • 标准化处理
          • 调用api根据提示词/个性化知识库进行个性化的标准处理
            • 由LLM 标注初始优先级，综合对个人的价值、信息密度等多个指标生成，用于调度
              • 优先级可随时快捷修改，指标也可个性化修改
            • 打标签，便于后续渐进写作时导入指定位置且带有容易筛选的标签
            • 其他个性化处理
              • 汉密尔顿阅读法
                • 可以将一份外文材料+母语材料生成双语阅读材料
                • 没有母语材料的，可以由LLM 生成母语材料
              • 发挥你的创造力！
        • 渐进学习
          • 渐进阅读
            • 已实现的功能将 Readwise reader 的功能囊括在内，并支持更多个性化的操作
            • 可以选中文字，将材料中你所需要的 block 一键高亮，挖空，改写，评论
            • 点击归档后，会将施加了操作的 block 按个性化要求转化为可导入后续复习软件的 flashcard 材料。
            • 个性化结构
              • 高亮内容，将原文提取出来，可自动导入复习软件的作为一张反面空白的 card，或自动导入PKM工具中的指定节点/文件夹 下方
              • 挖空内容，提取上下文，LLM 微调制作成通顺的挖空/问答卡
              • 评论结构，根据你自己设定的个性化提示词，生成个性化的格式
                • 批判
                • 引用
                • 补充
                • 作为论点的例子
              • 提问
                • 可在右侧插件面板进行全局或局部选中后的提问，调用 API 由AI结合 原文/知识库 作答，支持连续多轮提问。
                • 最终内容会整合转化为问答卡。
            • 辅助功能
              • 个性化主题
                • 纸书格式
              • 语言学习特化辅助功能
                • tts
                  • 较完善的基本 tts 功能
                  • 一些个性化的tts功能
                    • 朗读
                    • 语音相关制卡
                • 覆盖划词制卡的功能
                • 初学者友好的Bionic Reading
              • 数理学习特化辅助功能
          • 渐进写作
            • 实质上指的是作用于精华内容的间隔重复与渐进写作的合并工作流。
            • 将长文本拆成用于间隔重复或渐进写作的block
          • 该分类的原理
            • 渐进阅读的最终目标是渐进写作
            • 渐进阅读不能直接套用面向 Flashcard 间隔重复的 FSRS 等算法
              • 渐进阅读的概念定义及其宏观目标是相对清晰的
              • 但对于渐进阅读，如何（甚至是否有可能）将这一目标进一步形式化（formalization）为可优化的算法问题，目前尚未形成共识；现有实现往往直接套用 Flashcard 的间隔重复框架
                • 对于 Flashcard，学习状态可以通过可观测/潜在状态变量进行建模，例如“保留率（retrievability）” “记忆稳定度（stability）”等，并利用量化反馈进行参数估计与调度优化
                • 而“渐进阅读算法”目前仍基本处于尚未完成问题形式化的前范式阶段（pre-paradigmatic stage）：其状态变量、目标函数、反馈信号均尚未形成初步共识（目前甚至几乎没有多少独立于flashcard的尝试）
                  • “是否记住一个原子化的内容”是可被衡量的
                  • 但“一段阅读文本的记忆程度”目前仍是一个欠定义（under-defined) 的概念 ，即使是对同一文本，不同个体的需求完全不同
                    • 需要记住文本中的哪些内容
                    • 不同阅读目的下“记住”的标准是否相同
                    • 记忆到什么粒度
                    • （全文复刻除外，该类应原子化后归为flashcard）
                  • 更何况，对文本的调度，不只是依赖记忆相关参量，还要考虑到文本随时可能变化的优先级，这又牵扯到一系列难以量化且高度耦合的问题
              • 而渐进阅读的产物如果已经足够原子化，虽然部分背面空白卡，仍不能算 Flashcard （因为无测试效应），但相对来说对间隔重复算法的适配性会更强
                • 因此，我选择在渐进阅读阶段只对文章加以原始的优先级调度。
                • 当产生渐进阅读的产物之后
                  • 对flashcard，应用间隔重复算法。
                  • 渐进写作的 block ，只需在写作时自然与之相遇即可（带有简单的优先级调度）
                • 当然这仍不够理想，笔者仍在优化并积极思考新的解决方案
      • 前两个大模块是通用的，无论使用什么知识管理软件或复习软件都适用。
      • 渐进学习模块中
        • 渐进阅读环节配置在 Obsidian 上
        • 间隔重复加渐进写作的工作流配置在 RemNote 上。
      • 这是结合软件功能和开发难度综合做出的选择。
        • Obsidian 的插件生态开源插件最多，vibe coding开发最方便。
        • RemNote 是目前把 Flashcard +渐进写作功能做得最好的 PKM 软件。
      • 即使不使用 Obsidian 和 RemNote，这套方案、工作流和个人工具的开发思路仍有参考借鉴和改写的意义。
        • 也可以使用 Agent 开发对你来说更顺手、更个性化的方案。
        • Obsidian 可以换成 Logseq、RemNote、思源等一系列支持导入 Markdown 的软件
        • RemNote 可以换成 Anki 等一系列支持 Flashcard 的软件（但渐进写作的实现可能相对困难）
    • 虽然说是开箱即用，但毕竟是建立在 Obsidian 和 RemNote 的基础上，所以需要对这两个软件的使用有一定基本了解
    • 一些实际使用场景与全流程工作流
